name: Dashboard design direction
description: The user wants a simple skills-first career wizard, not the earlier graph-first simulator.
---

The user wants a clean, step-by-step skills-first wizard. They explicitly rejected the graph-first simulator as overwhelming: “It looks like a messy spiderweb and the judges won't understand it.” Results should use a calm workspace with a collapsible icon sidebar and one focused section at a time. The visual direction is a visible white geometric backdrop and a left-aligned frosted sidebar with a shaded border and dark text. The dashboard should fill the remaining width to the right, rather than stay in a centered narrow container. Only a separate background box should follow the pointer; the wallpaper itself must remain stationary.

**Why:** Hackathon judges need to understand the journey immediately; clarity now takes priority over the earlier immersive graph direction. The user later specified collapsible navigation, isolated section views, and a light interactive canvas. Their latest clarification replaces the centered-content direction with full-width results and limits pointer movement to the decorative box.

**How to apply:** Keep the skills-first flow and exclude the graph from the main view. In results, keep Overview, Recommendations, Route, and Skills/SDGs as separate views; keep role tabs keyboard-accessible and synchronize the selected role across views. Keep Moderate/Fast inside Recommendations, not in the top bar. Preserve data accuracy, fill the available results width beside the frosted sidebar, and keep the white geometric wallpaper fixed while a decorative box moves smoothly with the pointer.
